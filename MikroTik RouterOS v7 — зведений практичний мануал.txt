Коротка пряма відповідь

Зробив один великий структурований документ по RouterOS v7 (25 розділів, від архітектури пакетного потоку до готових .rsc-шаблонів). Але одразу чесно про головне обмеження: механічно «злити» весь help.mikrotik.com + весь форум в один файл неможливо — це тисячі сторінок документації й сотні тисяч тем форуму, плюс це чужий захищений контент. Тому документ — це витяжка практичних знань у форматі, придатному для копіювання, з картою офіційних джерел для поглиблення.

Що всередині
CLI, find/where, safe-mode, export/import та специфіка .rsc
Bridge VLAN filtering з трьома класичними помилками, через які втрачають доступ
Firewall: packet flow, еталонний базовий набір, raw, anti-bruteforce, fasttrack-пастка
NAT (включно з hairpin і netmap), QoS (simple/PCQ/queue tree)
VPN: WireGuard, IPsec S2S та IKEv2 road-warrior, L2TP, EoIP
Multi-WAN: рекурсивні маршрути, PCC, VRRP, netwatch
Скриптова мова, scheduler, fetch, приклади
Чеклист безпеки, процедура апгрейду, таблиця «симптом → причина»
Окремо під ваш генератор конфігів

Розділ 21 зроблено саме під програмну генерацію .rsc: таблиця числових меж (distance 1–255, vlan-id 1–4094, vrid 1–255, ASN, порти), формати й regex для MAC/CIDR/WG-ключів, і — головне — коректний порядок екранування (\ → " → $ → control chars), з поясненням, чому екранування не рятує структуровані поля. Там же описано саме той вектор, що фігурував у вашому код-ревʼю: MAC з імпортованого JSON, який завершується ; /user add ... group=full.

Ризики та обмеження
Версійна прив'язка: орієнтир — 7.23.x (остання stable на серпень 2026 — 7.23.3). Меню MikroTik змінює між мінорними релізами, тому кожну команду варто звіряти через ? у CLI.
Кілька місць я свідомо сформулював обережно, бо не можу перевірити точний синтаксис у вашому релізі: поля client-* у WireGuard peers, типи перевірок netwatch, співвідношення /container і нового меню /app. Вони позначені в тексті як «перевірте на своїй версії».
Приклади не враховують специфіку моделі (switch chip, hw-offload, LTE, регуляторний домен Wi-Fi).
Трюк зі «страхувальним ребутом» (4.4) працює лише в парі з /system backup load — RouterOS зберігає зміни одразу, на відміну від Cisco.
Наступні кроки
Якщо потрібно — можу розгорнути будь-який розділ у повноцінну главу (наприклад, BGP-фільтри v7 або CAPsMAN).
Можу перетворити розділ 21 на готовий модуль валідації для вашого PWA — єдине джерело правди замість трьох дублів, які знайшло ревʼю.
Якщо хочете, зроблю зворотний артефакт: набір «золотих» .rsc-шаблонів, які ваш генератор має відтворювати байт-у-байт — це хороша основа для регресійних тестів.  MikroTik RouterOS v7 — зведений практичний мануал

0. Про цей документ: що це і чого тут немає
Чесно про обсяг. Офіційна документація help.mikrotik.com — це кілька тисяч сторінок, а форум forum.mikrotik.com — сотні тисяч тем. Механічно «зібрати їх усі в один файл» неможливо і юридично (авторське право MikroTik), і технічно (обсяг більший за будь-який один документ). Тому цей мануал — структурована витяжка практичних знань: те, що реально використовується у 95% конфігурацій, у форматі, придатному для копіювання в .rsc.

Що всередині:

робочий синтаксис команд RouterOS v7 з прикладами;
типові архітектурні схеми (VLAN, firewall, VPN, failover);
підводні камені, через які ламаються конфіги;
довідник діапазонів і форматів значень — корисний для валідації в генераторах конфігів;
карта офіційної документації з посиланнями на розділи.
Чого немає і що треба перевіряти окремо:

повних таблиць параметрів кожної команди — вони є тільки в офіційному Help;
специфіки конкретних моделей (switch chip, PoE, LTE-модеми, регуляторні домени) — це завжди per-model;
гарантії, що синтаксис не змінився у вашій версії — MikroTik змінює меню між мінорними релізами (приклади: перехід /interface wireless → /interface wifi, поява меню /app поверх /container).
Правило №1 при роботі з цим мануалом: перед застосуванням перевіряйте команду на своїй версії через вбудовану довідку: /ip firewall filter add ? або /interface/wireguard/peers/print detail.

2. Базова архітектура RouterOS
2.1 Пакети (packages)
RouterOS модульний. /system/package/print покаже встановлені. Ключові:

Пакет	Призначення
routeros	ядро системи (в v7 більшість функцій вбудовано сюди)
wireless	старий стек Wi-Fi (/interface wireless, старий CAPsMAN)
wifi-qcom / wifi-qcom-ac / wifi-mediatek	новий стек Wi-Fi (/interface wifi), Wi-Fi 5/6/7
container	запуск OCI-контейнерів
user-manager	RADIUS-сервер
iot, lora, gps, zerotier, tailscale	додаткові
/system package print
/system package enable wifi-qcom
/system package disable wireless
/system reboot
wireless і wifi-qcom не можуть працювати одночасно на одному пристрої — тільки один стек активний.

2.2 Шлях пакета (packet flow) — мінімально необхідна модель
Для firewall/QoS критично розуміти порядок:

Вхід  → [raw prerouting] → [conntrack] → [mangle prerouting] → [dst-nat]
      → routing decision
        ├─ на роутер   → [mangle input]   → [filter input]   → локальний процес
        └─ транзит     → [mangle forward] → [filter forward] → [mangle postrouting] → [src-nat] → вихід
Локально згенерований → routing → [mangle output] → [filter output] → [mangle postrouting] → [src-nat]
Практичні наслідки:

dst-nat відбувається ДО маршрутизації → правила forward бачать уже підмінену адресу призначення (внутрішню);
src-nat/masquerade — ПІСЛЯ forward → у forward видно оригінальну адресу джерела;
raw працює до conntrack → сюди кидають дроп сміття/DDoS, щоб не навантажувати таблицю з'єднань;
маркування маршрутів (mark-routing) працює тільки у prerouting (для транзиту) і output (для трафіку самого роутера).
2.3 Hardware offload
Bridge, switch chip, fasttrack і IPsec можуть оброблятись апаратно. Наслідок: трафік, який пішов в offload, може не потрапляти у firewall/queue. Якщо правило «не спрацьовує» — перше, що перевіряють, це hw=yes на bridge-портах і fasttrack.

4. CLI: синтаксис, який треба знати напам'ять
4.1 Структура команди
/шлях/до/меню дія параметр=значення параметр=значення
Еквівалентні форми:

/ip/firewall/filter/add chain=input action=drop
/ip firewall filter add chain=input action=drop
4.2 Пошук і масові операції
# find повертає список внутрішніх ID
/ip address print where interface=ether1
/ip firewall filter remove [find comment="tmp"]
/interface set [find type=ether] mtu=1500
/ip dhcp-server lease print where dynamic=no

# оператори у where: = ! < > ~ (regex), and/or/not
/log print where message~"login failure"
/ip route print where dst-address in 10.0.0.0/8
4.3 Порядок правил і переміщення
Firewall, mangle, queue tree, routing rules — порядково залежні.

/ip firewall filter move [find comment="allow-vpn"] destination=0
/ip firewall filter print stats          # лічильники пакетів/байтів
/ip firewall filter reset-counters-all
4.4 Safe mode — обов'язково при віддаленій роботі
У терміналі: Ctrl+X (увімк./вимк.). Якщо сесія обривається — усі зміни, зроблені в safe mode, відкочуються автоматично.
Safe mode має обмежений буфер змін; великі конфіги можуть його переповнити.
Додатковий страхувальний прийом:
/system scheduler add name=rollback start-time=startup interval=0 \
  on-event="/system reset-configuration no-defaults=no skip-backup=no" disabled=yes
# або простіше:
/system scheduler add name=panic interval=5m on-event="/system reboot"
# ...застосовуєте ризиковані зміни, перевіряєте зв'язок, потім:
/system scheduler remove panic
(Роутер перезавантажиться і підніметься зі старої конфігурації, якщо ви не встигли зняти таймер — за умови, що зміни не збережені у startup-конфігурації. Для RouterOS зміни зберігаються одразу, тому цей трюк працює лише в парі з /system backup load у скрипті.)

4.5 Export / Import — основа роботи з .rsc
/export                          # уся конфігурація, тільки non-default значення
/export file=backup-2026-09-21   # у файл .rsc
/export compact                  # стисло
/export verbose                  # усі параметри, включно з дефолтними
/export terse                    # один рядок на команду — зручно для diff
/export show-sensitive           # ВКЛЮЧИТИ паролі/ключі (за замовчуванням приховані!)
/ip firewall export file=fw      # експорт окремої гілки
/import file-name=config.rsc
/import file-name=config.rsc verbose=yes
Критично про .rsc:

/export за замовчуванням ховає секрети (show-sensitive вимкнено з v7). Конфіг, відновлений з такого файлу, матиме порожні PSK/паролі/приватні ключі.
/import виконується порядково і зупиняється на першій помилці — частина конфігурації залишиться застосованою. Для ідемпотентності обгортайте:
:do { /ip address add address=10.0.0.1/24 interface=ether1 } on-error={ :log warning "addr exists" }
.rsc не портується між архітектурами так само погано, як бінарний backup — це його перевага. Бінарний /system backup прив'язаний до заліза; .rsc — текстовий і переносний (але імена інтерфейсів відрізняються!).
Перед імпортом на «чистий» пристрій:
/system reset-configuration no-defaults=yes skip-backup=yes
# після перезавантаження:
/import file-name=config.rsc
4.6 Backup vs Export
/system backup	/export
Формат	бінарний	текстовий .rsc
Містить	усе, включно з ключами, сертифікатами, користувачами	тільки конфіг; секрети — за show-sensitive
Переносимість	тільки та сама модель/архітектура	між пристроями (з правками)
Редагування	ні	так
/system backup save name=fullbackup password=SuperSecret encryption=aes-sha256
/system backup load name=fullbackup password=SuperSecret
5. Перший запуск і скидання
5.1 Default configuration (defconf)
Нові пристрої мають defconf-скрипт: bridge для LAN-портів, DHCP-сервер 192.168.88.0/24, WAN на ether1 з DHCP-клієнтом, базовий firewall.

/system default-configuration print
/system reset-configuration no-defaults=yes     # повне очищення
/system reset-configuration keep-users=yes
/system reset-configuration run-after-reset=myconfig.rsc
5.2 Netinstall
Для «цегли», забутого пароля, зміни архітектури пакетів. Потрібен ПК у тій самій L2-мережі, Etherboot/reset-кнопка. Netinstall завжди повністю стирає конфігурацію і файли.

6. Інтерфейси, bridge і VLAN
6.1 Interface lists — фундамент чистого конфігу
/interface list add name=WAN
/interface list add name=LAN
/interface list member add list=WAN interface=ether1
/interface list member add list=LAN interface=bridge1
Далі у firewall використовуємо in-interface-list=WAN замість імен — конфіг стає переносним.

6.2 Bridge
/interface bridge add name=bridge1 protocol-mode=rstp
/interface bridge port add bridge=bridge1 interface=ether2
/interface bridge port add bridge=bridge1 interface=ether3
/ip address add address=192.168.10.1/24 interface=bridge1
protocol-mode=none|stp|rstp|mstp — у домашній мережі часто rstp; у провайдерських схемах STP вимикають свідомо.
hw=yes на порту = апаратний offload через switch chip (тільки для портів одного чипа).
6.3 VLAN — три робочі схеми
A. VLAN на фізичному інтерфейсі (router-on-a-stick):

/interface vlan add name=vlan10 vlan-id=10 interface=ether1
/ip address add address=10.10.10.1/24 interface=vlan10
B. Bridge VLAN filtering (правильний спосіб для комутації):

/interface bridge add name=bridge1 vlan-filtering=no
/interface bridge port add bridge=bridge1 interface=ether2 pvid=10
/interface bridge port add bridge=bridge1 interface=ether3 pvid=20
/interface bridge port add bridge=bridge1 interface=ether10           # trunk, pvid=1

/interface bridge vlan add bridge=bridge1 vlan-ids=10 tagged=bridge1,ether10 untagged=ether2
/interface bridge vlan add bridge=bridge1 vlan-ids=20 tagged=bridge1,ether10 untagged=ether3

/interface vlan add name=v10 vlan-id=10 interface=bridge1
/interface vlan add name=v20 vlan-id=20 interface=bridge1
/ip address add address=10.10.10.1/24 interface=v10
/ip address add address=10.10.20.1/24 interface=v20

/interface bridge set bridge1 vlan-filtering=yes      # ОСТАННІМ рядком!
Три класичні помилки, через які «пропадає доступ»:

vlan-filtering=yes увімкнено до створення bridge VLAN — ви відрізаєте себе. Завжди останнім кроком і тільки в safe mode.
Забули додати bridge1 у tagged= для VLAN, на якому живе IP-адреса роутера. Сам bridge — це теж порт.
Управляючий VLAN не збігається з pvid порту, з якого ви під'єднані.
C. Switch chip VLAN (/interface ethernet switch) — застаріла схема для старих чипів; у v7 рекомендовано bridge VLAN filtering з hw=yes.

6.4 Bonding
/interface bonding add name=bond1 slaves=ether5,ether6 mode=802.3ad \
  transmit-hash-policy=layer-2-and-3 lacp-rate=30secs
Режими: balance-rr, active-backup, balance-xor, broadcast, 802.3ad (LACP, потрібна підтримка на комутаторі), balance-tlb, balance-alb.

6.5 MTU / L2MTU
mtu — L3 payload (зазвичай 1500).
l2mtu — максимальний Ethernet-фрейм; для VLAN/MPLS/tunnel потрібен запас.
Для VLAN поверх ether: l2mtu батьківського має бути ≥ l2mtu VLAN + 4.
Симптом невідповідності: ping проходить, HTTPS/SSH «підвисають» → класична MTU/MSS-проблема.
/ip firewall mangle add chain=forward action=change-mss new-mss=clamp-to-pmtu \
  protocol=tcp tcp-flags=syn out-interface-list=WAN
7. IP-рівень
7.1 Адресація
/ip address add address=192.168.10.1/24 interface=bridge1 comment="LAN gw"
/ip address print detail
network= обчислюється автоматично; вказувати не треба.

7.2 DHCP-сервер
/ip pool add name=pool-lan ranges=192.168.10.100-192.168.10.200
/ip dhcp-server add name=dhcp-lan interface=bridge1 address-pool=pool-lan lease-time=1d
/ip dhcp-server network add address=192.168.10.0/24 gateway=192.168.10.1 \
  dns-server=192.168.10.1 domain=lan.local
/ip dhcp-server enable dhcp-lan

# статична прив'язка
/ip dhcp-server lease add address=192.168.10.50 mac-address=AA:BB:CC:DD:EE:FF \
  server=dhcp-lan comment="printer"

# опції (наприклад, TFTP-сервер для IP-телефонії)
/ip dhcp-server option add name=tftp code=66 value="s'10.0.0.5'"
/ip dhcp-server option sets add name=voip options=tftp
7.3 DHCP-клієнт (WAN)
/ip dhcp-client add interface=ether1 use-peer-dns=no use-peer-ntp=no \
  add-default-route=yes default-route-distance=1
7.4 DNS
/ip dns set servers=1.1.1.1,9.9.9.9 allow-remote-requests=yes cache-size=4096
/ip dns static add name=nas.lan address=192.168.10.20
/ip dns static add regexp=".*\\.doubleclick\\.net" address=0.0.0.0
DoH (DNS over HTTPS):

/tool fetch url=https://curl.se/ca/cacert.pem
/certificate import file-name=cacert.pem passphrase=""
/ip dns set use-doh-server=https://cloudflare-dns.com/dns-query verify-doh-cert=yes
⚠ allow-remote-requests=yes без firewall-правила робить роутер відкритим DNS-резолвером → участь в DNS-амплифікаційних атаках. Обов'язково блокуйте UDP/TCP 53 з WAN.

7.5 ARP
/interface set bridge1 arp=reply-only
/ip arp add address=192.168.10.50 mac-address=AA:BB:CC:DD:EE:FF interface=bridge1
arp=reply-only + статичні записи = простий контроль доступу L2 (обходиться, але відсікає випадкових).

8. Маршрутизація
8.1 Статичні маршрути
/ip route add dst-address=0.0.0.0/0 gateway=192.168.1.1 distance=1 comment="ISP1"
/ip route add dst-address=0.0.0.0/0 gateway=10.20.30.1 distance=2 comment="ISP2 backup"
/ip route add dst-address=172.16.0.0/16 gateway=192.168.10.254
/ip route add dst-address=10.99.0.0/24 type=blackhole
Ключові параметри:

distance — адміністративна відстань, діапазон 1–255; менше = пріоритетніше;
check-gateway=ping|arp — прибирає маршрут, якщо шлюз не відповідає;
scope / target-scope — для рекурсивних маршрутів (за замовчуванням 30/10);
routing-table= — таблиця (VRF або policy routing);
vrf-interface= — для VRF-сценаріїв;
pref-src= — адреса джерела для трафіку, згенерованого роутером.
8.2 Рекурсивна маршрутизація (правильний failover)
check-gateway=ping перевіряє лише сусідній шлюз. Якщо ISP «живий», а його аплінк мертвий — маршрут залишиться. Рішення — рекурсія через публічний хост:

/ip route add dst-address=8.8.8.8 gateway=192.168.1.1 scope=10 comment="probe ISP1"
/ip route add dst-address=1.1.1.1 gateway=10.20.30.1 scope=10 comment="probe ISP2"

/ip route add dst-address=0.0.0.0/0 gateway=8.8.8.8 target-scope=10 distance=1 check-gateway=ping
/ip route add dst-address=0.0.0.0/0 gateway=1.1.1.1 target-scope=10 distance=2 check-gateway=ping
Обов'язково додайте NAT/маршрут так, щоб probe-адреси ходили тільки своїм каналом, інакше перевірка втратить сенс.

8.3 ECMP (балансування)
/ip route add dst-address=0.0.0.0/0 gateway=192.168.1.1,10.20.30.1 distance=1
ECMP балансує по з'єднаннях, не по пакетах. Мінус: сесії можуть «стрибати» після зміни таблиці conntrack — для HTTPS-банкінгу це проблема. Для передбачуваності краще PCC-mangle або policy routing.

8.4 Policy routing (окремі таблиці)
/routing table add name=via-isp2 fib

/ip firewall mangle add chain=prerouting src-address=192.168.10.0/25 \
  action=mark-routing new-routing-mark=via-isp2 passthrough=no in-interface=bridge1

/ip route add dst-address=0.0.0.0/0 gateway=10.20.30.1 routing-table=via-isp2

# альтернатива без mangle — routing rules
/routing rule add src-address=192.168.10.0/25 action=lookup-only-in-table table=via-isp2
8.5 VRF
/ip vrf add name=CUST-A interfaces=ether4,vlan100
/ip address add address=172.20.0.1/24 interface=vlan100
/ip route add dst-address=0.0.0.0/0 gateway=172.20.0.254 routing-table=CUST-A
VRF ізолює таблиці маршрутизації. Для доступу між VRF потрібні route leaking або firewall-міст.

8.6 Динамічна маршрутизація (коротко)
OSPF (v7-синтаксис принципово відрізняється від v6!):

/routing ospf instance add name=default router-id=10.0.0.1
/routing ospf area add name=backbone area-id=0.0.0.0 instance=default
/routing ospf interface-template add interfaces=bridge1 area=backbone \
  type=ptp cost=10 auth=md5 auth-key="secret" auth-id=1
/routing ospf interface-template add interfaces=bridge2 area=backbone passive=yes
BGP (v7-синтаксис):

/routing bgp template set default as=65001 router-id=10.0.0.1
/routing bgp connection add name=upstream remote.address=192.0.2.1 remote.as=65000 \
  local.role=ebgp templates=default address-families=ip \
  output.filter-chain=bgp-out input.filter=bgp-in

/routing filter rule add chain=bgp-out rule="if (dst in 203.0.113.0/24) { accept } reject"
У v7 фільтри — це скриптова мова (/routing filter rule), а не набір полів як у v6. Це найчастіша причина болю при міграції.

9. Firewall
9.1 Ланцюги і таблиці
Таблиця	Ланцюги	Призначення
filter	input, forward, output	дозволити/заборонити
nat	srcnat, dstnat	трансляція адрес
mangle	prerouting, input, forward, output, postrouting	маркування, MSS, TTL, DSCP
raw	prerouting, output	до conntrack — дешевий дроп
Дії: accept, drop, reject, jump, return, log, passthrough, fasttrack-connection, add-src-to-address-list, add-dst-to-address-list, tarpit, dst-nat, src-nat, masquerade, netmap, redirect, mark-connection, mark-packet, mark-routing, change-mss, change-ttl, change-dscp, notrack, sniff-tzsp.

9.2 Еталонний базовий набір (можна копіювати)
/ip firewall address-list
add list=RFC1918 address=10.0.0.0/8
add list=RFC1918 address=172.16.0.0/12
add list=RFC1918 address=192.168.0.0/16
add list=MGMT address=192.168.10.0/24 comment="admin subnet"

/ip firewall filter
# --- INPUT ---
add chain=input action=accept connection-state=established,related comment="est,rel"
add chain=input action=drop connection-state=invalid comment="invalid"
add chain=input action=accept protocol=icmp limit=10,20:packet comment="icmp rate-limited"
add chain=input action=accept src-address-list=MGMT comment="mgmt access"
add chain=input action=accept in-interface-list=LAN comment="LAN to router"
add chain=input action=drop in-interface-list=WAN comment="drop all from WAN"
add chain=input action=drop comment="default drop"

# --- FORWARD ---
add chain=forward action=fasttrack-connection connection-state=established,related \
    hw-offload=yes comment="fasttrack"
add chain=forward action=accept connection-state=established,related
add chain=forward action=drop connection-state=invalid
add chain=forward action=accept in-interface-list=LAN out-interface-list=WAN comment="LAN->WAN"
add chain=forward action=accept connection-nat-state=dstnat comment="port forwards"
add chain=forward action=drop comment="default drop"

/ip firewall nat
add chain=srcnat action=masquerade out-interface-list=WAN comment="NAT out"
Про fasttrack: різко знижує навантаження CPU, але fasttrack-нуті пакети не проходять через mangle/queue/filter. Якщо потрібен QoS — виключіть відповідний трафік з fasttrack або не вмикайте його зовсім.

9.3 RAW — для великого сміттєвого трафіку
/ip firewall raw
add chain=prerouting action=drop src-address-list=RFC1918 in-interface-list=WAN comment="bogons in"
add chain=prerouting action=drop dst-address-list=RFC1918 in-interface-list=WAN
add chain=prerouting action=notrack dst-port=53 protocol=udp in-interface-list=LAN
9.4 Захист від брутфорсу SSH/Winbox (класичний ланцюжок)
/ip firewall filter
add chain=input protocol=tcp dst-port=22 src-address-list=ssh_blacklist action=drop
add chain=input protocol=tcp dst-port=22 connection-state=new \
    action=add-src-to-address-list address-list=ssh_stage3 address-list-timeout=1m \
    src-address-list=ssh_stage2
add chain=input protocol=tcp dst-port=22 connection-state=new \
    action=add-src-to-address-list address-list=ssh_stage2 address-list-timeout=1m \
    src-address-list=ssh_stage1
add chain=input protocol=tcp dst-port=22 connection-state=new \
    action=add-src-to-address-list address-list=ssh_stage1 address-list-timeout=1m
add chain=input protocol=tcp dst-port=22 src-address-list=ssh_stage3 \
    action=add-src-to-address-list address-list=ssh_blacklist address-list-timeout=10d
Порядок рядків тут критичний — вони мають йти саме так (blacklist → stage3 → stage2 → stage1).

9.5 Connection tracking
/ip firewall connection tracking set enabled=auto tcp-established-timeout=1d
/ip firewall connection print where protocol=tcp
connection-state: new, established, related, invalid, untracked. connection-nat-state: srcnat, dstnat — незамінне для правил під port forwarding.

9.6 Layer7 — з обережністю
/ip firewall layer7-protocol дуже дорогий по CPU і працює лише на перших пакетах з'єднання. Для блокування сайтів краще: DNS-static, address-list з FQDN (/ip firewall address-list add list=X address=example.com — RouterOS сам резолвить), або TLS-SNI matcher (tls-host= у firewall filter).

/ip firewall filter add chain=forward action=reject protocol=tcp dst-port=443 \
  tls-host="*.example.com"
10. NAT
10.1 Masquerade vs src-nat
/ip firewall nat add chain=srcnat action=masquerade out-interface-list=WAN
# статична зовнішня адреса — краще src-nat (дешевше, стабільніше при reconnect)
/ip firewall nat add chain=srcnat action=src-nat to-addresses=203.0.113.10 out-interface=ether1
masquerade при падінні інтерфейсу скидає conntrack-записи; src-nat — ні.

10.2 Port forwarding (dst-nat)
/ip firewall nat add chain=dstnat action=dst-nat in-interface-list=WAN \
  protocol=tcp dst-port=8080 to-addresses=192.168.10.20 to-ports=80 comment="web srv"
Не забудьте forward-правило (або connection-nat-state=dstnat accept як вище).

10.3 Hairpin NAT (доступ до свого сервера із внутрішньої мережі по зовнішньому імені)
/ip firewall nat add chain=dstnat action=dst-nat protocol=tcp dst-port=443 \
  dst-address=203.0.113.10 to-addresses=192.168.10.20
/ip firewall nat add chain=srcnat action=masquerade protocol=tcp dst-port=443 \
  src-address=192.168.10.0/24 dst-address=192.168.10.20
10.4 1:1 NAT (netmap)
/ip firewall nat add chain=dstnat action=netmap dst-address=203.0.113.16/28 \
  to-addresses=192.168.10.16/28
/ip firewall nat add chain=srcnat action=netmap src-address=192.168.10.16/28 \
  to-addresses=203.0.113.16/28
11. QoS
11.1 Simple queue — швидко і зрозуміло
/queue simple add name=user-50 target=192.168.10.50/32 max-limit=20M/20M
/queue simple add name=guest target=192.168.20.0/24 max-limit=50M/50M \
  queue=pcq-upload-default/pcq-download-default
Порядок: simple queue обробляються зверху вниз, перша збіжність виграє.

11.2 PCQ — справедливий розподіл між користувачами
/queue type add name=pcq-dl kind=pcq pcq-classifier=dst-address pcq-rate=0 pcq-limit=50
/queue type add name=pcq-ul kind=pcq pcq-classifier=src-address pcq-rate=0 pcq-limit=50
/queue simple add name=fair target=192.168.10.0/24 max-limit=100M/100M \
  queue=pcq-ul/pcq-dl
pcq-rate=0 = ділити порівну; pcq-rate=5M = жорсткий стель на користувача.

11.3 Queue tree + mangle (повноцінний QoS)
/ip firewall mangle
add chain=prerouting action=mark-connection new-connection-mark=voip-c \
    protocol=udp port=5060,10000-20000 passthrough=yes
add chain=prerouting action=mark-packet new-packet-mark=voip-p connection-mark=voip-c passthrough=no

/queue tree add name=WAN-out parent=ether1 max-limit=100M
/queue tree add name=voip parent=WAN-out packet-mark=voip-p limit-at=10M max-limit=20M priority=1
/queue tree add name=rest parent=WAN-out packet-mark=no-mark priority=8
Правила: limit-at = гарантія, max-limit = стеля, priority 1 (найвищий) – 8.

Queue tree на global бачить весь трафік; на конкретному інтерфейсі — лише вихідний з нього. І пам'ятайте про fasttrack (п. 9.2).

12. VPN
12.1 WireGuard — дефолтний вибір у v7
Сервер:

/interface wireguard add name=wg0 listen-port=13231 mtu=1420
/ip address add address=10.10.0.1/24 interface=wg0

/interface wireguard peers add interface=wg0 \
  public-key="CLIENT_PUB_KEY=" allowed-address=10.10.0.2/32 comment="laptop"

/ip firewall filter add chain=input action=accept protocol=udp dst-port=13231 comment="wg in"
/ip firewall filter add chain=forward action=accept in-interface=wg0 out-interface-list=LAN
Публічний ключ роутера: /interface wireguard print detail.

Site-to-site:

# на стороні А
/interface wireguard peers add interface=wg0 public-key="B_PUB=" \
  endpoint-address=203.0.113.20 endpoint-port=13231 \
  allowed-address=10.10.0.2/32,192.168.20.0/24 persistent-keepalive=25s
/ip route add dst-address=192.168.20.0/24 gateway=wg0
Нюанси:

allowed-address виконує роль і crypto-routing, і фільтра — вказуйте всі мережі за пірером;
persistent-keepalive потрібен, якщо сторона за NAT;
MTU 1420 — стартова точка; при проблемах з HTTPS зменшуйте або додайте MSS-clamping;
у новіших релізах з'явились зручності для генерації клієнтських конфігів/QR — перевірте наявність полів client-* у вашій версії (/interface/wireguard/peers/add ?).
12.2 IPsec site-to-site (IKEv2)
/ip ipsec profile add name=p-s2s enc-algorithm=aes-256 hash-algorithm=sha256 \
  dh-group=modp2048 lifetime=1d

/ip ipsec proposal add name=pr-s2s auth-algorithms=sha256 \
  enc-algorithms=aes-256-cbc,aes-256-gcm pfs-group=modp2048 lifetime=30m

/ip ipsec peer add name=peer-b address=203.0.113.20/32 exchange-mode=ike2 profile=p-s2s
/ip ipsec identity add peer=peer-b auth-method=pre-shared-key secret="STRONG_PSK"

/ip ipsec policy add peer=peer-b tunnel=yes proposal=pr-s2s \
  src-address=192.168.10.0/24 dst-address=192.168.20.0/24

# ОБОВ'ЯЗКОВО: виключити VPN-трафік з NAT
/ip firewall nat add chain=srcnat action=accept place-before=0 \
  src-address=192.168.10.0/24 dst-address=192.168.20.0/24
Пропуск останнього правила — причина №1 «тунель піднявся, але трафік не ходить».

Порти для firewall: UDP 500, UDP 4500 (NAT-T), протокол 50 (ESP). Діагностика: /ip ipsec active-peers print, /ip ipsec installed-sa print, /log print where topics~"ipsec".

12.3 IKEv2 road-warrior (mode-config)
/ip ipsec mode-config add name=rw-cfg address-pool=vpn-pool address-prefix-length=32 \
  split-include=192.168.10.0/24 static-dns=192.168.10.1 system-dns=no
/ip pool add name=vpn-pool ranges=10.50.0.10-10.50.0.100

/ip ipsec policy group add name=rw
/ip ipsec profile add name=rw-prof enc-algorithm=aes-256 hash-algorithm=sha256 dh-group=modp2048
/ip ipsec peer add name=rw exchange-mode=ike2 passive=yes profile=rw-prof

/ip ipsec identity add peer=rw auth-method=digital-signature certificate=server-cert \
  generate-policy=port-strict mode-config=rw-cfg policy-template-group=rw
/ip ipsec policy add group=rw template=yes dst-address=10.50.0.0/24 src-address=0.0.0.0/0 \
  proposal=pr-s2s
Потрібні сертифікати (/certificate) з правильними SAN — інакше iOS/macOS/Windows клієнти не підключаться.

12.4 L2TP/IPsec (сумісність з усім)
/interface l2tp-server server set enabled=yes use-ipsec=required ipsec-secret="PSK" \
  default-profile=vpn-profile authentication=mschap2
/ppp profile add name=vpn-profile local-address=10.60.0.1 remote-address=vpn-pool \
  dns-server=192.168.10.1 change-tcp-mss=yes
/ppp secret add name=user1 password="..." service=l2tp profile=vpn-profile
Порти: UDP 500, 1701, 4500.

12.5 OpenVPN (OVPN)
RouterOS історично підтримував лише TCP; у v7 додано UDP. Нюанси сумісності з клієнтами високі — використовуйте WireGuard, якщо немає вимоги на OVPN.

/interface ovpn-server server set enabled=yes certificate=server-cert \
  auth=sha256 cipher=aes256-gcm mode=ip default-profile=vpn-profile require-client-certificate=yes
12.6 SSTP
Проходить крізь будь-який HTTPS-проксі (TCP 443), але тільки Windows нативно.

12.7 L2-тунелі: EoIP, GRE, VXLAN
/interface eoip add name=eoip1 remote-address=203.0.113.20 tunnel-id=100 \
  ipsec-secret="PSK" allow-fast-path=no
/interface bridge port add bridge=bridge1 interface=eoip1
EoIP прозоро розтягує L2 — і разом з ним broadcast-штормів. Завжди думайте про STP і MTU.

12.8 ZeroTier / Tailscale
Доступні як пакети/контейнери на пристроях з достатньою пам'яттю. Зручно для швидкого mesh-доступу без публічної IP. Перевіряйте доступність пакета для вашої архітектури.

13.4 Практичні поради
country= обов'язково — від нього залежать дозволені канали й потужність (і законність);

14. Multi-WAN і відмовостійкість
14.1 Три рівні резервування
Маршрут з distance + check-gateway — найпростіше, але «сліпе» (див. 8.2).
Рекурсивні маршрути — перевірка реальної доступності Інтернету.
Netwatch + скрипти — довільна логіка (перемикання, сповіщення, зміна NAT).
14.2 Netwatch
/tool netwatch add host=8.8.8.8 interval=10s timeout=1s \
  up-script="/ip route enable [find comment=ISP1]" \
  down-script="/ip route disable [find comment=ISP1]; /log warning \"ISP1 down\""
У новіших версіях netwatch підтримує типи перевірок (type=simple|http-get|https-get) — перевіряйте /tool netwatch add ? на своїй версії.

14.3 VRRP (резервування самого роутера)
/interface vrrp add name=vrrp1 interface=bridge1 vrid=10 priority=200 \
  preemption-mode=yes authentication=ah password="secret"
/ip address add address=192.168.10.254/24 interface=vrrp1
На backup-роутері — та сама конфігурація з priority=100. Клієнти отримують 192.168.10.254 як шлюз.

14.4 PCC (балансування по з'єднаннях)
/ip firewall mangle
add chain=prerouting in-interface-list=LAN connection-mark=no-mark \
    per-connection-classifier=both-addresses:2/0 action=mark-connection new-connection-mark=to-isp1
add chain=prerouting in-interface-list=LAN connection-mark=no-mark \
    per-connection-classifier=both-addresses:2/1 action=mark-connection new-connection-mark=to-isp2
add chain=prerouting connection-mark=to-isp1 action=mark-routing new-routing-mark=isp1 in-interface-list=LAN
add chain=prerouting connection-mark=to-isp2 action=mark-routing new-routing-mark=isp2 in-interface-list=LAN
Не забудьте: окремі routing-table, маршрути в них, NAT по out-interface, і правила для трафіку самого роутера (chain=output).

19.3 Міграція v6 → v7 — на що дивитись
OSPF і BGP переписані повністю (див. 8.6) — конфіг не переноситься автоматично коректно у складних випадках;
/interface wireless → рекомендовано /interface wifi (потребує ручної перебудови);
зміни у /routing filter (тепер скриптова мова);
/ip route — нові параметри таблиць і VRF;
деякі меню перейменовано (/ip firewall service-port, /system health тощо).
Не оновлюйте v6 → v7 «в один крок» на віддаленому критичному пристрої без консолі або другого каналу доступу.

21.3 Екранування в .rsc — критично для безпеки
RouterOS console трактує подвійні лапки як рядок з підстановкою. Усередині "...":

$ починає підстановку змінної → має бути екранований як \$;
\ — екранувальний символ → \\;
" → \";
символи керування: \n, \r, \t, \_ (пробіл), \a, \b, \f, \v;
довільний байт: \XX (hex).
Поза лапками руйнівними є: пробіл, ; (розділювач команд), перенос рядка, { }, [ ].

Мінімальний коректний порядок екранування (важливий саме порядок!):

1) \  →  \\
2) "  →  \"
3) $  →  \$
4) керуючі символи → \XX
5) обгорнути результат у "..."
Якщо $ екранувати до \, отримаєте подвійне екранування і зламаний рядок.

Приклад безпечної функції (псевдокод JS):

function q(v) {
  return '"' + String(v)
    .replace(/\\/g, '\\\\')
    .replace(/"/g,  '\\"')
    .replace(/\$/g, '\\$')
    .replace(/[\x00-\x1F\x7F]/g, c =>
        '\\' + c.charCodeAt(0).toString(16).toUpperCase().padStart(2, '0'))
    + '"';
}
Чого екранування НЕ рятує: поля, які не можуть бути рядком у лапках — числа, enum-и, імена інтерфейсів у деяких контекстах, MAC-адреси, IP. Їх треба валідувати за whitelist-патерном, а не екранувати. Типова вразливість генератора конфігів: MAC-адреса з імпортованого профілю вставляється як є → AA:BB:CC:DD:EE:FF; /user add name=evil password=x group=full виконується як окрема команда.

Правило: структуровані поля → whitelist-regex; вільний текст (comment, ssid, passphrase, identity) → лапки + екранування; числа → парсинг + перевірка діапазону.

26. IPv6 — повний робочий цикл
26.1 Увімкнення
IPv6 у RouterOS v7 вбудовано в основний пакет, але може бути вимкнено:

/ipv6 settings set disable-ipv6=no forward=yes accept-router-advertisements=no
На маршрутизаторі accept-router-advertisements=no — правильний дефолт. Інакше роутер сам починає слухати RA з WAN і ставити маршрути.

26.2 Отримання префікса від провайдера (DHCPv6-PD)
/ipv6 dhcp-client add interface=ether1 request=prefix pool-name=isp-pool \
  pool-prefix-length=64 add-default-route=yes use-peer-dns=no

/ipv6 address add address=::1 from-pool=isp-pool interface=bridge-lan advertise=yes
address=::1 from-pool=... означає «взяти перший /64 з делегованого префікса і дати роутеру адресу ...::1».

26.3 Роздача клієнтам
SLAAC (найпростіше):

/ipv6 nd set [find default=yes] interface=bridge-lan advertise-dns=yes \
  managed-address-configuration=no other-configuration=no ra-lifetime=30m
/ipv6 nd prefix default set autonomous=yes preferred-lifetime=1d valid-lifetime=2d
DHCPv6-сервер (коли потрібні фіксовані адреси):

/ipv6 pool add name=lan-pool prefix=2001:db8:1::/48 prefix-length=64
/ipv6 dhcp-server add name=dhcp6 interface=bridge-lan address-pool=lan-pool
/ipv6 nd set [find] managed-address-configuration=yes other-configuration=yes
Android історично не підтримує DHCPv6 — якщо в мережі є Android-пристрої, SLAAC обов'язковий (або SLAAC+DHCPv6 разом).

26.4 Firewall для IPv6 — не забувайте
IPv6 — це глобально маршрутизовані адреси без NAT. Без firewall уся ваша LAN доступна з Інтернету.

/ipv6 firewall address-list
add list=bad_ipv6 address=::1/128 comment="lo"
add list=bad_ipv6 address=::ffff:0.0.0.0/96 comment="ipv4-mapped"
add list=bad_ipv6 address=2001:db8::/32 comment="documentation"
add list=bad_ipv6 address=fe80::/10 comment="link-local"

/ipv6 firewall filter
add chain=input action=accept connection-state=established,related
add chain=input action=drop connection-state=invalid
add chain=input action=accept protocol=icmpv6 comment="ICMPv6 is MANDATORY"
add chain=input action=accept protocol=udp dst-port=546 src-address=fe80::/10 comment="dhcpv6"
add chain=input action=accept in-interface-list=LAN
add chain=input action=drop

add chain=forward action=accept connection-state=established,related
add chain=forward action=drop connection-state=invalid
add chain=forward action=accept protocol=icmpv6
add chain=forward action=drop src-address-list=bad_ipv6
add chain=forward action=drop dst-address-list=bad_ipv6
add chain=forward action=accept in-interface-list=LAN
add chain=forward action=drop
Не блокуйте ICMPv6 наосліп. На відміну від IPv4, в IPv6 ICMP несе NDP (заміна ARP) і PMTUD. Блокування = мережа не працює. Максимум — rate-limit.

26.5 NAT66 / масквардинг IPv6
Технічно можливий (/ipv6 firewall nat action=masquerade), але не рекомендований: ламає e2e, PMTUD і частину протоколів. Використовують лише коли провайдер видає один /128 без делегування. Альтернатива — NPTv6 (action=netmap).

Hotspot працює через прозорий проксі — HTTPS-редирект неможливий коректно без сертифіката, довіреного клієнтом. Сучасні ОС використовують captive portal detection (captive.apple.com, connectivitycheck.gstatic.com) — додайте їх у walled garden, щоб спливало вікно логіну.

login-by=mac дозволяє автологін за MAC — зручно і небезпечно одночасно.

29. MPLS і VPLS (оглядово)
Актуально для провайдерських мереж. Мінімальний L2VPN:

/mpls ldp add transport-addresses=10.255.0.1 lsr-id=10.255.0.1 enabled=yes
/mpls ldp interface add interface=ether1
/mpls settings set dynamic-label-range=16-1048575

/interface vpls add name=vpls-to-B remote-peer=10.255.0.2 vpls-id=1:100 \
  cisco-style=no disabled=no
/interface bridge port add bridge=bridge-l2 interface=vpls-to-B
Вимоги:

IGP (OSPF) має бути піднятий і стабільний — MPLS будується поверх нього;
MTU: MPLS додає 4 байти на мітку → потрібен jumbo-capable транспорт (l2mtu ≥ 1526+);
lsr-id і transport-address — зазвичай loopback (/interface bridge add name=lo + адреса /32).
Діагностика: /mpls ldp neighbor print, /mpls forwarding-table print, /mpls local-mapping print.

MPLS на MikroTik — потужний, але чутливий до MTU і версій. Для 2–3 офісів простіше EoIP/WireGuard.

30. Bridge: просунуті можливості
30.1 MSTP
/interface bridge set bridge1 protocol-mode=mstp region-name=REGION1 region-revision=1
/interface bridge msti add bridge=bridge1 identifier=1 priority=0x8000
/interface bridge port set [find interface=ether2] internal-path-cost=10
MSTP дозволяє різним VLAN мати різні активні топології. Усі комутатори в регіоні мусять мати однакові region-name, region-revision і мапінг VLAN→MSTI.

30.2 Bridge filter і bridge NAT (фільтрація на L2)
/interface bridge filter add chain=forward action=drop mac-protocol=ipx
/interface bridge filter add chain=input action=drop src-mac-address=AA:BB:CC:00:00:00/FF:FF:FF:00:00:00
/interface bridge nat add chain=dstnat action=dst-nat to-dst-mac-address=... 
/interface bridge settings set use-ip-firewall=yes змушує мостовий трафік проходити через IP firewall — дорого по CPU, вмикати тільки свідомо.

30.3 Port isolation (horizon)
/interface bridge port set [find interface=ether2] horizon=1
/interface bridge port set [find interface=ether3] horizon=1
Порти з однаковим horizon не обмінюються трафіком між собою (аналог private VLAN). Дешевше, ніж окремі VLAN для кожного клієнта.

30.4 QinQ (802.1ad, service VLAN)
/interface bridge set bridge1 vlan-filtering=yes ether-type=0x88a8
/interface vlan add name=svlan100 vlan-id=100 interface=ether1 use-service-tag=yes
/interface vlan add name=cvlan10 vlan-id=10 interface=svlan100
Потрібен запас MTU (+4 байти на кожну мітку) і підтримка з боку чипа.

30.5 Інші корисні параметри порту
Параметр	Що робить
hw=yes	апаратний offload (тільки порти одного switch chip)
edge=yes	порт доступу — швидший перехід у forwarding
bpdu-guard=yes	вимикає порт, якщо прийшов BPDU (захист від підключення чужого комутатора)
frame-types	admit-all, admit-only-untagged-and-priority-tagged, admit-only-vlan-tagged
ingress-filtering=yes	відкидати кадри з VLAN, не дозволеними на порту
unknown-unicast-flood=no	обмеження флуду
multicast-router / IGMP snooping	/interface bridge set bridge1 igmp-snooping=yes
Для VLAN-безпеки завжди: ingress-filtering=yes + frame-types=admit-only-untagged-and-priority-tagged на портах доступу.

31. Switch chip і hardware offload
31.1 Що треба розуміти
Кожен пристрій має свій чип: Atheros8327, QCA8337, Marvell Prestera, MT7621, тощо. Можливості різні: підтримка VLAN offload, ACL rules, mirroring, кількість записів у таблицях.
Offload працює тільки між портами одного чипа. Порти на різних чипах або через CPU — програмна обробка.
/interface ethernet switch print покаже наявні чипи; /interface bridge port print — колонку H (hardware offload активний).
31.2 Перевірка
/interface ethernet switch print
/interface bridge port print detail where hw=yes
/interface ethernet switch rule print       # ACL на рівні чипа (не на всіх моделях)
/interface ethernet switch port print
31.3 Чому offload «злітає»
Типові причини втрати H=yes:

на bridge увімкнено use-ip-firewall=yes;
порт у bonding;
змішані типи портів (SFP + ether різних чипів);
увімкнено певні режими STP чи mirroring;
інтерфейс — VLAN/тунель, а не фізичний порт.
31.4 Дзеркалювання портів
/interface ethernet switch set 0 mirror-source=ether2 mirror-target=ether5

35.7 Готовий приклад: авто-бан за логами
/system script add name=scan-auth source={
    :foreach l in=[/log find where topics~"system" && message~"login failure"] do={
        :local m [/log get $l message]
        :local p [:find $m "from "]
        :if ($p > 0) do={
            :local ip [:pick $m ($p+5) [:find $m " via"]]
            :if ([:len [/ip firewall address-list find list=banned address=$ip]] = 0) do={
                /ip firewall address-list add list=banned address=$ip timeout=1d \
                    comment="auto: failed login"
                :log warning ("banned " . $ip)
            }
        }
    }
}
/system scheduler add name=scan-auth interval=2m on-event=scan-auth
Приклад демонстраційний: формат рядків логу відрізняється між версіями. Перед продакшеном перевірте /log print руками.

36. API: бінарний і REST
36.1 Бінарний API (8728 / 8729 TLS)
Протокол простий і добре підходить для автоматизації:

Повідомлення = sentence — послідовність words, завершена word нульової довжини.
Кожне word має префікс довжини змінного розміру:
Довжина	Кодування префікса
< 0x80	1 байт: len
< 0x4000	2 байти: len | 0x8000, big-endian
< 0x200000	3 байти: len | 0xC00000
< 0x10000000	4 байти: len | 0xE0000000
більше	1 байт 0xF0 + 4 байти довжини
Перше word — команда (/interface/print), далі атрибути (=name=value), query-слова (?type=ether), і теги (.tag=1).
Відповіді: !re (дані), !done (кінець), !trap (помилка), !fatal.
Логін у сучасних версіях — одним sentence:
/login
=name=admin
=password=secret
(старий MD5-challenge механізм підтримувався до 6.43; у v7 не потрібен).

Готові бібліотеки: librouteros (Python), routeros_api (Python), routeros-api (PHP), go-routeros (Go), node-routeros (JS).

POST   https://router/rest/execute           {"script":"/system/resource/print"}
Особливості:

потребує www-ssl з сертифікатом (див. 32);
.id має вигляд *3 — у URL використовується без зірочки або з нею залежно від версії, перевіряйте;
для команд без CRUD використовується POST /rest/<path>/<command>, напр. POST /rest/system/reboot.

39. Продуктивність і планування ємності
39.1 Де витрачається CPU
Firewall/conntrack — кількість правил × пакети. Оптимізація: раннє accept established,related, raw для сміття, address-list замість десятків правил, fasttrack.
Queue — особливо queue tree з багатьма гілками і PCQ з великим pcq-limit.
Шифрування — IPsec/WireGuard/OVPN. Дивіться, чи є апаратне прискорення IPsec (/system resource print → наявність ipsec в hw).
Wi-Fi — обробка кадрів.
Логування — рясний action=log у firewall здатен покласти роутер.
39.2 Правила оптимізації firewall
# ПОГАНО: 50 правил з окремими IP
# ДОБРЕ: один address-list
/ip firewall address-list add list=blocked address=1.2.3.0/24
/ip firewall filter add chain=forward action=drop src-address-list=blocked

# ПОГАНО: log на кожен дроп
# ДОБРЕ: log з обмеженням
/ip firewall filter add chain=input action=log log-prefix="DROP" limit=5,10:packet
39.3 Орієнтири (дуже приблизні, перевіряйте на своєму залізі)
hEX/RB750-клас: 100–300 Мбіт/с з NAT+firewall, значно менше з queue/VPN;
hAP ax-клас: ~1 Гбіт/с з fasttrack;
CCR2004/CCR2116: десятки Гбіт/с, IPsec з апаратним прискоренням;
CHR: залежить від vCPU і vNIC (virtio + multiqueue дає в рази більше).
Єдиний правильний спосіб знати цифри — /tool profile duration=10 під реальним навантаженням.

40.4 Історична безпека — чому оновлення критичні
RouterOS мав публічно відомі вразливості, які масово експлуатувалися (найвідоміший приклад — обхід автентифікації Winbox у v6, що призвів до масового зараження криптомайнером і ботнетами). Уроки:

не виставляйте Winbox/API/WWW у публічний Інтернет ніколи;
оновлюйтесь регулярно, особливо long-term гілку на критичних пристроях;
після підозри на компрометацію: /system reset-configuration no-defaults=yes + Netinstall + зміна всіх паролів, а не «почистити скрипти». Перевірте /system scheduler, /system script, /ip socks, /ip proxy, /tool fetch у планувальнику, /file print, /user print — класичні місця закріплення.

    :if ([/ip service get [find name=telnet] disabled] = false) do={ :log warning "telnet ON" }
    :if ([/ip service get [find name=api] disabled] = false) do={ :log warning "api ON" }
    :if ([/ip dns get allow-remote-requests] = true) do={ :log info "check DNS firewall" }
    :if ([:len [/user find name=admin disabled=no]] > 0) do={ :log warning "default admin enabled" }

        :log warning "no default drop in input" }

41. Лабораторія і тестування
CHR (Cloud Hosted Router) — образ RouterOS для VMware/Hyper-V/KVM/VirtualBox/хмар. Безкоштовна ліцензія: 1 Мбіт/с на інтерфейс — достатньо для тестів конфігу.

Мінімальний цикл перевірки нового .rsc: підняти чистий CHR → /import → перевірити код виходу і /log print where topics~"error" → прогнати smoke-скрипт (37.3).
# автоматизована перевірка імпорту
:local errBefore [:len [/log find where topics~"error"]]
:do { /import file-name=test.rsc } on-error={ :log error "IMPORT FAILED" }
:local errAfter [:len [/log find where topics~"error"]]
:if ($errAfter > $errBefore) do={ :log error "errors during import" }
42. Генерація .rsc: ідемпотентність і порядок
Продовження розділу 21 першої частини. Це найважливіша частина для вашого сценарію — програмної генерації конфігів.

42.1 Проблема
/import — це послідовне виконання команд, а не декларативне застосування стану. Наслідки:

повторний імпорт створює дублікати (два однакові firewall-правила, дві адреси);
команда add падає, якщо об'єкт існує з унікальним полем;
помилка на рядку N зупиняє виконання, залишаючи рядки 1..N-1 застосованими.
42.2 Три стратегії
A. Clean-slate (найпростіша і найнадійніша)

/system reset-configuration no-defaults=yes skip-backup=yes run-after-reset=config.rsc
Плюс: гарантований детермінований результат. Мінус: обрив зв'язку, потрібен фізичний/OOB-доступ.

B. Секційне очищення перед записом

/ip firewall filter remove [find]
/ip firewall nat remove [find]
/ip firewall filter add ...
Плюс: не чіпає решту конфігу. Мінус: момент, коли firewall порожній (використовуйте /system scheduler для атомарного застосування або safe mode).

C. Ідемпотентні операції (upsert за коментарем)

:local cmt "gen:nat:wan-masq"
:if ([:len [/ip firewall nat find comment=$cmt]] > 0) do={
    /ip firewall nat set [find comment=$cmt] action=masquerade out-interface-list=WAN
} else={
    /ip firewall nat add comment=$cmt action=masquerade chain=srcnat out-interface-list=WAN
}
Патерн «comment як зовнішній ID» — найкраща практика для генераторів: RouterOS не має стабільних ID між перезавантаженнями (*3 змінюється), тому коментар з префіксом (gen:) стає ключем. Правило: усе, що створює генератор, отримує коментар із префіксом; все з цим префіксом можна безпечно видалити при повній перегенерації:

/ip firewall filter remove [find comment~"^gen:"]
42.3 Порядок команд — граф залежностей
Генератор мусить випускати команди у топологічно коректному порядку:

1. /interface bridge, /interface bonding, /interface vlan   (створення L2)
2. /interface list, /interface list member
3. /interface bridge port, /interface bridge vlan
4. vlan-filtering=yes                                        ← ТІЛЬКИ ПІСЛЯ п.3
5. /ip pool
6. /ip address
7. /ip dhcp-server, /ip dhcp-server network
8. /ip dns
9. /routing table                                            ← перед маршрутами з routing-table
10. /ip route
11. /ip firewall address-list
12. /ip firewall mangle → nat → filter                        (порядок усередині кожної таблиці критичний)
13. /interface wireguard → /interface wireguard peers
14. /ip ipsec profile → proposal → peer → identity → policy
15. /queue type → /queue simple або /queue tree
16. /system script → /system scheduler
17. /user, /ip service                                        ← в кінці (ризик обриву)
Типові порушення, які ламають імпорт:

маршрут із routing-table=X до створення /routing table add name=X;
interface list member з інтерфейсом, який ще не створено;
queue з packet-mark, якого ще немає в mangle (RouterOS це дозволить, але правило буде мертве);
/ip address на VLAN-інтерфейсі до його створення;
IPsec policy до peer/proposal.
42.4 Порядок усередині firewall
Правила додаються в кінець. Якщо генератор випускає їх у потрібному порядку — все добре. Якщо ж вставляє в існуючий набір — використовуйте place-before:

/ip firewall filter add chain=forward action=drop comment="gen:guest-isolation" \
  place-before=[find comment="gen:lan-to-wan"]
place-before приймає ID. Якщо find нічого не знайшов, команда впаде — обгортайте в :do {} on-error={} або перевіряйте довжину.

42.5 Безпечний «шапка/підвал» згенерованого файлу
# ==== generated by <tool> v1.4 on 2026-09-21T10:00:00Z ====
# target: RouterOS 7.20+ / device: hEX S
:global GENFAIL false
:do {
    ... основна частина ...
} on-error={
    :set GENFAIL true
    :log error "generated config import FAILED"
}
:if ($GENFAIL = false) do={ :log info "generated config applied OK" }
43. .rsc: edge cases парсера
Перелік речей, які регулярно ламають згенеровані файли:

Ситуація	Що відбувається	Як обробляти в генераторі
Ім'я інтерфейсу з пробілом ("ether1 - WAN")	команда розбивається на дві	завжди лапки навколо імен, або заборонити пробіли у власних іменах
Коментар із ;	решта рядка — нова команда	екранувати + лапки (див. 21.3)
Коментар із $	підстановка змінної → порожньо або сміття	\$
Порожнє значення (comment=)	синтаксична помилка	comment=""
Багаторядкове значення (скрипт у source=)	{} блок, всередині свої правила	вкладати як source={...}, стежити за балансом фігурних дужок
Не-ASCII (кирилиця в comment/ssid)	залежить від кодування файлу	зберігати .rsc у UTF-8 без BOM
BOM на початку файлу	перший рядок не розпізнається	не писати BOM
CRLF vs LF	зазвичай ок, але краще LF	нормалізувати
Дуже довгий рядок	обмеження консолі	розбивати логічно, не посеред значення
Коментар-рядок #	працює тільки на початку рядка	не ставити # у середині
Продовження рядка	символ \ в кінці рядка	використовувати обережно, краще довгі рядки
[ ] у рядковому значенні	всередині подвійних лапок підстановка команд не виконується, але поза лапками — виконується	завжди лапки для вільного тексту
find повернув порожньо	set [] — no-op, place-before=[] — помилка	перевіряти [:len ...]
Пароль, що починається з - чи містить \	ламає парсинг	лапки + екранування
0 замість no у boolean	помилка типу	приводити до yes/no
Число з провідним нулем чи пробілом	port= 80 — помилка	trim + приведення типу
43.1 Мінімальний набір валідаторів для генератора
const V = {
  ipv4:   s => /^(25[0-5]|2[0-4]\d|1?\d?\d)(\.(25[0-5]|2[0-4]\d|1?\d?\d)){3}$/.test(s),
  cidr4:  s => { const [a,b]=String(s).split('/');
                 return V.ipv4(a) && /^\d{1,2}$/.test(b) && +b>=0 && +b<=32; },
  mac:    s => /^([0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2}$/.test(s),
  vlan:   n => Number.isInteger(+n) && +n>=1   && +n<=4094,
  port:   n => Number.isInteger(+n) && +n>=1   && +n<=65535,
  dist:   n => Number.isInteger(+n) && +n>=1   && +n<=255,
  vrid:   n => Number.isInteger(+n) && +n>=1   && +n<=255,
  wgkey:  s => /^[A-Za-z0-9+/]{43}=$/.test(s),
  ifname: s => /^[A-Za-z0-9_.\-]{1,32}$/.test(s),   // без пробілів — свідоме обмеження
  timeSpec: s => /^(\d+[wdhms])+$|^\d{2}:\d{2}:\d{2}$/.test(s),
};
Правило розподілу:

структуроване поле (IP, MAC, VLAN, порт, ключ, enum) → whitelist-валідація, без лапок; при невдачі — відмова генерувати, а не «санітизація»;
вільний текст (comment, ssid, identity, passphrase, name) → лапки + екранування за 21.3;
числа → парсинг у ціле + перевірка діапазону + повторна серіалізація (не передавати рядок користувача).
Ключова теза: санітизація структурованих полів небезпечна. Якщо MAC не проходить regex — це помилка вводу або атака; «почистити» його і продовжити означає згенерувати конфіг, якого користувач не очікує. Відмова краща.

43.2 Що перевіряти на рівні семантики (не синтаксису)
IP-адреса шлюзу належить одній із підмереж пристрою (або досяжна через інший маршрут);
адреса з /32 як LAN-мережа — майже завжди помилка;
pool не перетинається зі статичними адресами і адресою шлюзу;
dst-nat на приватну адресу, якої немає в жодній локальній мережі;
два дефолтні маршрути з однаковим distance (несвідомий ECMP);
VLAN ID, використаний двічі на одному bridge;
out-interface посилається на інтерфейс, якого немає в конфігурації;
правило accept після drop у тому самому ланцюзі — мертвий код;
відсутність default drop в input при наявності WAN.

Приклад авто-бану за логами (35.7) залежить від формату повідомлень логу, який змінювався між версіями — перевіряйте на реальних даних.
Орієнтири продуктивності (39.3) — дуже приблизні; це порядок величини, не специфікація.
Таблиця сумісності (44) відображає основні зламні зміни, але не є вичерпною — MikroTik вносить дрібні зміни майже в кожному мінорному релізі.
MPLS, dot1x, User Manager і Hotspot подані оглядово: кожна з цих тем заслуговує окремого документа такого ж обсягу.
